# Онлайн-магазин 

Веб-приложение на базе Django, представляющее собой современный каталог товаров с адаптивным интерфейсом, системой обратной связи и полноценным контентным блогом для улучшения SEO-показателей сайта.
Интерфейс страниц стилизован с помощью фреймворка Bootstrap.

## 🚀 Функционал

## 🔐 Модуль аутентификации и разграничения доступа

В рамках защиты сервиса от спам-ботов реализована полноценная система управления пользователями с авторизацией по электронной почте.

### Функционал модуля:
* **Кастомная модель пользователя (`User`):** Базовая модель расширена на основе `AbstractUser`. Авторизация переведена со стандартного `username` на уникальный `email`. Добавлены дополнительные поля: аватар (изображение), номер телефона и страна.
* **Регистрация с валидацией:** Создана форма регистрации с кастомной валидацией паролей. Система проверяет совпадение основного пароля и поля подтверждения (`password_confirm`). При обнаружении нестыковок пользователю выводится информативное сообщение.
* **Приветственные уведомления:** Настроена автоматическая отправка email-сообщения на адрес пользователя сразу после успешного создания учетной записи (интегрирован консольный почтовый бэкенд для тестирования).
* **Авторизация и сессии:** Реализован защищенный вход в систему по связке Email + Пароль с обработкой ошибок аутентификации через Django Messages Framework. В навигационной панели динамически отображается текущий статус сессии и email вошедшего пользователя.
* **Безопасный выход:** Разлогин пользователя переведен на метод `POST` в соответствии с современными стандартами безопасности Django для предотвращения CSRF-атак через GET-запросы.

### 🛡️ Безопасность и Middleware
Для надежной защиты эндпоинтов от несанкционированного доступа разработан кастомный компонент общего уровня — `LoginRequiredMiddleware`:
1. Он автоматически перехватывает все входящие HTTP-запросы к приложению.
2. Гарантирует, что неавторизованные гости (анонимы) имеют доступ **исключительно** к трем эндпоинтам: главная страница каталога (`catalog:home`), страница входа (`users:login`) и страница регистрации (`users:register`).
3. При любой попытке анонимного пользователя обратиться к закрытым страницам управления продуктами (детализация, создание, редактирование или удаление товара) middleware автоматически блокирует запрос и перенаправляет гостя на страницу авторизации.

### 🛒 Модуль «Каталог» и управление продуктами (CRUD)
* **Главная страница (Каталог):** Отображение списка доступных товаров в виде адаптивных карточек с автоматической обрезкой длинного описания до 100 символов для сохранения единого стиля интерфейса.
* **Страница товара (Детализация):** Отдельная страница для каждого продукта с выводом полной информации (название, категория, детальное описание, цена и изображение) и возможностью возврата в каталог.
* **Управление продуктами (CRUD):** Реализован полный цикл создания, редактирования и удаления товаров через специализированные формы.
* **Страница контактов:** Вывод контактных данных компании и интерактивной формы обратной связи с валидацией полей, защитой от ошибок и автоматическим сохранением сообщений в базу данных.
* **Архитектура шаблонов (DRY):** Реализован сквозной базовый шаблон (`base.html`), содержащий общие стили, скрипты, шапку и подвал сайта. Выделен повторно используемый подшаблон (`header.html`) для динамического вывода приветствия.
* **Управление данными (ORM):** Созданы модели продуктов (`Product`), категорий (`Category`) и сообщений обратной связи (`ContactMessage`) со связями `ForeignKey`.
* **Панель администратора:** Настроена кастомная админка с фильтрацией по категориям, поиском по названию/описанию и выводом ключевых полей.
* **Управление через фикстуры:** Реализовано сохранение и загрузка тестовых данных в формате JSON.
* **Кастомные команды:** Добавлена консольная команда для быстрой очистки БД и перезаполнения её данными из фикстур.

### 📝 Модуль «Блог» (SEO-оптимизация)
* **Полный CRUD-цикл:** Реализована полноценная система управления статьями (просмотр списка, чтение, создание, редактирование и удаление публикаций).
* **Модель блоговой записи (`BlogPost`):** Хранит заголовок, содержимое, превью-изображение, дату создания, признак публикации и счетчик просмотров. Настроена правильная сортировка контента (сначала новые).

## 🛡 Валидация и безопасность форм 

Для защиты сайта от спама и некорректных данных внедрены строгие механизмы валидации в `ProductForm`:
1. **Фильтрация запрещенных слов (Анти-спам):** 
   В константу `FORBIDDEN_WORDS` вынесен список стоп-слов (*казино, криптовалюта, крипта, биржа, дешево, бесплатно, обман, полиция, радар*). В методах `clean_name()` и `clean_description()` проверяется отсутствие этих слов в полях названия и описания товара. Регистр букв полностью игнорируется (`.lower()`). При совпадении вызывается исключение `ValidationError`.
2. **Контроль стоимости продукта:** 
   В методе `clean_price()` реализована проверка на знак вводимого числа. Ввод отрицательной стоимости блокируется на уровне формы и выводит пользователю информативное сообщение об ошибке.
3. **Универсальная стилизация полей (Bootstrap):** 
   В методе `__init__` формы динамически перебираются все поля. Текстовые, числовые и файловые поля автоматически получают класс `form-control`. Чекбоксы (при их наличии) получают специализированный класс `form-check-input`, гарантируя корректное отображение всех элементов интерфейса в едином Bootstrap-стиле.

## 🛠 Проделанный рефакторинг и кастомная логика

1. **Перевод архитектуры на CBV (Class-Based Views):**
   Все существовавшие ранее контроллеры в приложении `catalog` и новом приложении `blog` были успешно переведены с функциональных представлений (FBV) на представления на основе классов (CBV), такие как `ListView`, `DetailView`, `CreateView`, `UpdateView` и `DeleteView`.
2. **Динамический счетчик просмотров статьи:** 
   Реализовано автоматическое увеличение просмотров на `+1` при каждом открытии статьи (переопределен метод `get_object` в `DetailView`).
3. **Фильтрация опубликованного контента:** 
   В общем списке статей блога отображаются только те записи, у которых установлен флаг «Опубликовано» (переопределен метод `get_queryset` в `ListView`).
4. **Умный редирект после редактирования:** 
   После успешного изменения статьи пользователь автоматически перенаправляется на страницу этой же статьи для контроля изменений (переопределен метод `get_success_url` в `UpdateView`).
5. **Строгая маршрутизация:** 
   Все URL-адреса спроектированы по стандартам Django: используют префикс `blogs/` для блога, подключены через `include` в основном конфигурационном файле и строго заканчиваются на закрывающий слэш `/`.

## Установка и запуск проекта

### 1. Клонирование репозитория и переход в папку
```bash
git clone <ссылка_на_репозиторий>
cd online-store-project
```

### 2. Установка зависимостей через Poetry
Убедитесь, что у вас установлен Poetry. Для установки окружения выполните:
```bash
poetry install
```

### 3. Настройка переменных окружения
Создайте файл `.env` в корневом каталоге проекта на основе шаблона `.env.sample` и заполните ваши доступы к PostgreSQL и секретный ключ Django:
```env
DB_NAME=имя_базы_данных
DB_USER=имя_пользователя
DB_PASSWORD=ваш_пароль
DB_HOST=127.0.0.1
DB_PORT=5432
SECRET_KEY=ваш_секретный_ключ
```

### 4. Активация виртуального окружения
```bash
poetry shell
```

### 5. Применение миграций базы данных
Создайте таблицы в СУБД PostgreSQL:
```bash
python manage.py migrate
```

### 6. Наполнение базы данных тестовыми данными
Запустите кастомную команду для автоматической очистки таблиц и загрузки актуальных фикстур:
```bash
python manage.py fill_db
```

### 7. Создание суперпользователя (для доступа в админку)
```bash
python manage.py createsuperuser
```

### 8. Запуск сервера разработки
```bash
python manage.py runserver
```

После запуска сервер будет доступен по адресу: `http://127.0.0`
